Self-consistency / majority voting across verifier samples. Sample the keep/drop verifier several times (temperature >0) on the same finding + context and keep only findings that survive a majority (or plurality) of samples. Cursor’s launch Bugbot ran eight parallel passes over a shuffled diff, bucketed similar findings, and dropped any bug found in only one pass; this was one of the most effective early quality steps before they moved to an agentic loop. https://cursor.com/blog/building-bugbot (15 Jan 2026). Self-consistency can backfire on hard science questions for small models, but execution-grounded variants help on code. Cost: N-1 extra model calls for N samples. Applies cleanly to a ~120B open model (Nemotron-class) as a pure sampling filter.
Require the verifier to quote evidence or name a failing input / counterexample. Force a keep decision to include a concrete code citation, a minimal failing input, or an executable counterfactual before accepting the finding. In Adversarial Review, an unconstrained reviewer–critic pair scored F1 0.457 on 100 real GitHub PR diffs (worse than a single reviewer at 0.495); requiring the critic to cite code for any disagreement raised the same pair to F1 0.533. https://arxiv.org/abs/2608.18167 (16 Aug 2026); https://agentpatterns.ai/code-review/evidence-grounded-disagreement/ (15 Oct 2026). A related fix-guided filter treats the model’s proposed patch as a testable counterfactual: if original fails and fix passes, keep; if both pass, drop. https://agentpatterns.ai/patterns/anti-patterns/llm-review-overcorrection/ (15 Oct 2026, citing arXiv:2603.00539). Cost: 0–1 extra calls (same prompt or one verification step). Applies directly to a keep/drop verifier; addresses the fact that raw 1–5 confidence scores did not separate true from false findings.
Debate or critic–defender setups. A second agent audits the finding under a structured protocol that forbids ungrounded agreement. The same Adversarial Review protocol (reviewer + evidence-constrained critic) improved F1 only when disagreement had to be grounded in code; naive agreement collapsed. Refute-or-Promote used adversarial kill mandates and a cross-model critic to discard ~79% of ~171 candidates before disclosure (prospective kill rate 83% on a 30-candidate subset). https://arxiv.org/html/2604.19049v1 (21 Apr 2026). Cost: 1–2 extra calls. Applies; a single critic pass on a 120B model is feasible.
Severity or “would block merge” calibration. Score findings and drop those below a high threshold (e.g., only P0/P1 or confidence ≥80). Anthropic’s open-source code-review plugin scores 0–100 and posts only findings ≥80, “dramatically reducing false positives.” https://claude.com/marketplace/plugins/code-review (accessed Oct 2026). Cubic’s explicit reasoning logs + confidence fields contributed to a 51% false-positive reduction without sacrificing recall. https://www.zenml.io/llmops-database/reducing-false-positives-in-ai-code-review-agents-through-architecture-refinement (production case, 2025). Pure self-scored severity was close to random for Greptile in 2024 and did not separate classes for TraceHound’s earlier verifier. Cost: 0 extra calls if scored in the same prompt. Applies, but low expected gain alone on a 120B model given the prior negative result.
Deduplication or clustering. Cluster near-duplicate findings (by line, function, or semantic similarity) and keep one representative. Uber merges similar comments; Cursor buckets then merges. https://www.cubic.dev/blog/how-ai-code-review-works (11 Oct 2026). Cost: near-zero model calls (post-processing). Applies; reduces volume more than pure precision/recall.
Running tests or static analysis as a filter. Run SAST first or verify by executing tests / a proposed fix. On Tencent’s industrial dataset of 433 alarms (328 false positives, 105 true positives), hybrid LLM + static-analysis methods (LLM4PFA, LLM4SA) eliminated 94–98% of false positives while maintaining high recall across GPT-4o, Claude-Opus-4, Qwen-3-Coder, and DeepSeek-R1. https://arxiv.org/html/2601.18844v1 (26 Jan 2026). QASecClaw (Semgrep + Qwen 3.5 Plus filter agent) cut false positives 88.6% (560 → 64) on the full OWASP Benchmark v1.2 (2,740 cases) with only a 3.1% recall drop, raising F1 from 0.784 to 0.909. https://arxiv.org/abs/2605.01885 (3 May 2026). Cost: 0 LLM calls if tests/SA already exist; 1 if the model must generate a test. Applies strongly whenever the repository has tests or a lightweight static checker can be run on the flagged location.
Verifier prompts told to keep when unsure. Bias the prompt toward retention to protect recall. Binary keep/drop prompts produced fewer false positives than explanatory ones in the overcorrection study; aggressive investigation prompts worked better once Bugbot became agentic and could gather context. Evidence of net gain for pure “keep if unsure” is weak and risks amplifying the known overcorrection bias. Cost: 0. Applies but low expected value.
Opinion ranking by expected gain per extra model call (for a keep/drop verifier on ~120B open weights):

Evidence-quoting / failing-input / fix-guided verification (highest gain, 0–1 extra call; directly fixes ungrounded keeps).
Multi-sample majority voting (solid production signal from Bugbot; cost scales with N but can start at 3–5 samples).
Structured critic with mandatory evidence (or lightweight test/SA gate when available) (1 extra call, strong empirical kill rates in both pure-LLM and hybrid settings).

Severity scoring alone and “keep when unsure” rank lower given TraceHound’s earlier negative result on numeric confidence.
