1. The five products (October 2026)
Cursor Bugbot is Cursor’s PR reviewer for logic, performance, and security issues. It moved from $40/seat/month to usage-based billing (average run $1.00–$1.50 depending on PR size/complexity) at each customer’s first renewal after 8 June 2026; effort levels (Low/Default/High/Smart) are available. https://cursor.com/blog/may-2026-bugbot-changes (11 May 2026); https://cursor.com/help/account-and-billing/bugbot-usage-based-billing (current). Internal resolution rate (share of flagged bugs fixed before merge, LLM-judged) rose from 52% to >70% after 40 experiments; later reports cite 78–80% at Default, with High finding ~35% more bugs at the same rate. It reviews >2 million PRs/month. https://cursor.com/blog/building-bugbot (15 Jan 2026). On Martian’s Code Review Bench (independent, open-source, 50-PR offline set with golden comments + LLM judge; online tracker of developer actions), Bugbot has appeared mid-pack (e.g., F1 ~57% in recent online views). https://codereview.withmartian.com (accessed Oct 2026); https://www.cubic.dev/blog/cursor-bugbot-review (15 Oct 2026).
CodeRabbit is a multi-host (GitHub, GitLab, Bitbucket, Azure DevOps) PR reviewer with CLI/IDE support. Pricing: Essentials $24/dev/month annual ($30 monthly), Team $48/$60, Advanced $72/$90; only PR authors count as seats; free on public repos; hourly rate limits (5–12 reviews/dev/hour) with optional overage. https://docs.coderabbit.ai/management/plans (15 Oct 2026); https://www.cubic.dev/blog/ai-code-review-pricing (4 Oct 2026). On Martian online (last-month views, checked Oct 2026) it scores ~61.8% F1; offline F2 has varied. Vendor and third-party numbers differ widely by setup. https://www.cubic.dev/blog/coderabbit-vs-greptile (4 Oct 2026); https://codereview.withmartian.com.
Greptile is a codebase-graph-aware reviewer (GitHub, GitLab, Bitbucket, Gitea; self-host option). Pro is $30/seat/month with 50 credits (Base review = 1 credit, Plus = 3, Apex = 10); $1/extra credit (not pooled); Starter free for 1 developer. https://www.greptile.com/docs/code-review-bot/billing-seats (26 Sep 2026); https://macroscope.com/content/greptile-pricing-2026 (9 Oct 2026). Martian online has shown it near the top (e.g., 61.9% F1, high precision ~79% in one Oct 2026 view). https://www.cubic.dev/blog/coderabbit-vs-greptile (4 Oct 2026).
Augment Code is an IDE-integrated coding assistant (VS Code, JetBrains, etc.) with a code-review feature on paid plans. Current self-serve plans are flat (no per-seat for up to 50 seats): Standard ~$20/month with included usage, Business ~$100/month; Enterprise custom. Pricing has changed multiple times. https://www.augmentcode.com/pricing (accessed Oct 2026). On Martian offline it has ranked high (e.g., strong F2/precision in some views). https://codereview.withmartian.com; https://thenewstack.io/github-reviewbench-code-review/ (6 Oct 2026).
GitHub Copilot code review is the built-in reviewer on paid Copilot plans (Pro $10, Pro+ $39, Max $100, Business $19/seat, Enterprise $39/seat). Reviews consume AI credits ($0.01 each; GitHub estimates $0.05–$1 Lite / $0.25–$5 Balanced default per review) plus Actions minutes on private repos since 1 June 2026. https://www.cubic.dev/blog/github-copilot-code-review (4 Oct 2026); https://usepoly.co/github-copilot-pricing (7 Oct 2026). On Martian it ranks mid-pack (e.g., ~60.9% F1 online, lower offline). On GitHub’s own ReviewBench it ranked #1. https://thenewstack.io/github-reviewbench-code-review/ (6 Oct 2026).
2. Other public benchmarks (2025–2026)

Martian Code Review Bench (launched Feb 2026, MIT, open): Offline = 50 real PRs (Sentry, Grafana, Cal.com, Discourse, Keycloak) with human-curated golden comments, scored by LLM judges (Claude Opus/Sonnet, GPT variants) for precision/recall/F-β (Strict/Core/All profiles). Online = continuous sampling of public PRs measuring whether developers act on comments. Dataset and pipeline public. https://codereview.withmartian.com; https://github.com/withmartian/code-review-benchmark (2026); https://mnemoverse.com/docs/library/ai-code-review-benchmarks (4 Oct 2026).
GitHub ReviewBench (5 Oct 2026, open): 219 public PRs from 187 repos across 19 languages, sampled to match distributions of 103.9 million GitHub PRs (size weighted toward reviewable changes). Multi-source golden set (human reviewers, author follow-ups, static analysis, frontier LLMs), scored by Claude Sonnet 5 with grounded (known issues) and augmented (new valid findings) precision/recall/F1, sliceable by severity/category. Dataset, rubric, judge, and runner public. https://github.blog/ai-and-ml/github-copilot/reviewbench-an-open-benchmark-for-ai-code-review/ (5 Oct 2026).
Others include Macroscope’s 118-bug production-bug set (vendor-run), Tenki’s per-bug scoring on a 50-PR/122-bug reverse-replay of a prior Greptile set, and various smaller vendor or academic sets (e.g., CRBugBench ~1,800 tasks). Most are not fully open. https://macroscope.com/content/greptile-vs-coderabbit-2026 (9 Oct 2026); https://tenki.cloud/blog/benchmarking-ai-code-reviewers (19 May 2026).

3. Developer comments (X, HN, Reddit 2025–2026)
Top complaints:

Noise / too many comments / false positives (most frequent). Examples: HN user called Greptile “pretty much pure noise” after 3 PRs and listed irrelevant suggestions (Python version, design nits); another said AI reviewers produce “a large number of false positive or inappropriate suggestions” so comments get ignored (1 in 10–20 useful). https://news.ycombinator.com/item?id=46777079; https://news.ycombinator.com/item?id=46349684. Reddit threads describe CodeRabbit dumping 30+ comments and teams building their own to tag Major/Minor/Nit. https://www.reddit.com/r/codereview/comments/1u3ecqm/we_hit_greptiles_new_1review_tax_and_coderabbits/ (11 Jun 2026); https://www.reddit.com/r/cicd/comments/1x4dcz7/opensource_maintainers_are_drowning_in_ai_slop/ (12 Oct 2026).
Cost unpredictability after usage billing.
Comments ignored or low action rate; review still bottleneck (Harvard study: review time +49% after agent adoption).

Praised: catches real bugs when tuned or with good context; learns from feedback; useful as second opinion or for nits humans miss. Frequency of “noise/false positives/too many comments” is high across the sampled threads—it is the dominant complaint.
4. LLM-as-judge self-preference bias
Strong evidence exists. A 2026 blind audit found every tested judge (GPT-4o, Claude Haiku/Sonnet) inflated its own family by a mean +0.14 win-rate points versus a neutral panel (GPT-4o +0.21); the bias is family-wide and not fully explained by self-recognition. https://github.com/hankimis/self-preference (2026). Rubric-based studies show judges >50% more likely to incorrectly mark a failing rubric as satisfied when the output is their own or same-family. https://arxiv.org/html/2604.06996v3 (2026). A quantification framework across 20 models found SPB often uncorrelated or negatively correlated with capability; a multi-dimensional strategy reduced it 31.5% on average. https://arxiv.org/abs/2604.22891 (24 Apr 2026, revised Jun 2026). Earlier work (NeurIPS 2024 workshop) already documented significant self-preference in GPT-4 linked to lower perplexity/familiarity. https://arxiv.org/abs/2410.21819 (29 Oct 2024, revised 2025).
Opinion: Single-LLM-judge scores (including TraceHound’s) should be treated as directional; cross-family panels or human spot-checks reduce risk.
