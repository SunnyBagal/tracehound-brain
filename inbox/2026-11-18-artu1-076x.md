# artu1: ruling 076x, 18 Nov 2026

Counts and method only. Ruling by Sunny on 18 Nov 2026; each line gives the reason.

- **Objects fetched from the wrong source are kept, as a recorded deviation.** While completing the held-out clones,
  the first fetch command added the upstream address as a second URL instead of replacing the existing one, so git
  kept using the original remote: 22,241 missing objects in two of the four clones came from there over plain git
  (no web page, API, review comments or writes). The fetcher caught and disclosed it; the rest (48,020 objects) came
  from the public upstream, with the address proven before each of 95 fetches. A second agent's identity check found
  every commit, tree and original head matching the manifest, with no other state changed. Sunny kept the objects.
  Reason: git objects are addressed by content, the identity check shows the cases are unchanged, and rebuilding
  changes nothing.
- **Condition, at no cost:** a full object-integrity check (`git fsck --full`) on the two affected clones, checked by a
  second agent, before anything continues; any corrupt or mismatched object means rebuilding those clones from the
  upstream, and goes back to Sunny. Reason: content addressing proves identity only for objects that are intact.
- **Dates:** the window now starts on the Thursday and ends 72 hours later on the Sunday; the two hand-check sittings
  are that Sunday afternoon (about 150 minutes) and the Monday. Nothing is unblinded until the last item is done.
  Reason: the freeze moved one day under the registered rule.
- **Lesson:** a git config override on the command line can add to a multi-valued setting rather than replace it;
  prove the effective URL before any fetch whose source matters.
